# タスクボード（Redmine カンバン）

Redmine 連携の軽量カンバン。各自のPCで動く中継プログラムがボードの画面を出し、社外の Redmine とつなぐ。

```
ブラウザ（http://127.0.0.1:8765/） ⇄ kanban_relay.py（各自のPC） ⇄ Redmine（社外）
```

SharePoint に置く方式は、SharePoint Online がページ内のスクリプトを止めるため採用しなかった。
また Redmine が CORS を許可しないため、ブラウザから Redmine へ直接はつなげない。

## ファイル

| ファイル | 用途 |
|---|---|
| `kanban_relay.py` | 配布する中継プログラム。ボードの画面(HTML)も埋め込まれている |
| `board_settings.example.json` | チームの設定の見本。`board_settings.json` にコピーして書き換える |
| `setup.bat` | 初回設定用（`kanban_relay.py` のダブルクリックでも同じ。.py が Python に関連付けられていない PC 用） |
| `src/kanban.fragment.html` | ボードの元ファイル。編集後に `python build.py` |
| `build.py` | ボードの HTML を作り、`kanban_relay.py` に埋め込む（確認用の `kanban.html` も作る） |
| `tools/redmine_config_dump.py` | Redmine の設定を一覧で確認する道具（通常は不要） |

## 配布と使い方

共有フォルダ（ファイルサーバーや、OneDrive で同期した SharePoint のフォルダ）に 3 つを置く。

```
共有フォルダ/
  kanban_relay.py
  board_settings.json   ← マネージャーが 1 回書く（見本: board_settings.example.json）
  setup.bat
```

`board_settings.json` に書くのは人が決めることだけ。

- `redmine_url` / `project`: Redmine の URL とプロジェクトの識別子
- `team`: タブに並べるメンバー。`"auto"` なら未完了のチケットを担当している人だけ。名前（Redmine の表示名）か ID の一覧を書けばその人だけ。
  どちらの場合も `team_exclude` に書いた人は出さない。プロジェクトの他のメンバーは出ない
- `team_order`: タブの並び順。書いた人がこの順で先頭、残りは後ろ
- `managers`: 「上司完了」と「全体」タブを扱える人。名前か ID（`12` でも `"12"` でもよい）。
  プロジェクトのメンバーでなくても、チケットの担当者・作成者か、中継を動かしている本人なら見つかる
- `status_columns`: 名前から列を推定できないステータスだけ指定（例 `{"保留": "todo"}`）
- `update_dir`: 更新を取りに行くフォルダ。空なら `setup.bat` を実行したフォルダ（`%USERPROFILE%` なども使える）
- `options`: `urgentPriority` / `dueSoonDays` / `approvedDays` / `versionColors`

ステータスの ID と列の対応、子チケット条件が使えるかは、起動時に Redmine から自動で読む。
読んだ結果は毎回 `%APPDATA%\DesignTaskBoard\detected_config.json` に上書き保存し、読めなかったときはこれを使う
（確認用の控えなので手で直さない。直すのは `board_settings.json`）。
起動時の注意（推定できないステータス、見つからないメンバー）は「接続設定」の下にも出る。

### メンバーの初回

1. 共有フォルダの `kanban_relay.py`（または `setup.bat`）をダブルクリック。
2. API キーを入力し、自動起動を「Y」。ボードが開き、デスクトップに「タスクボード」ができる。
3. 以降はログオン時に画面なしで起動する（このユーザーのレジストリ `HKCU\...\CurrentVersion\Run` に登録。
   タスクマネージャーの「スタートアップ」で確認・無効化できる）。ボードは http://127.0.0.1:8765/ （ポータルにこのリンクを貼ってもよい）。

### 更新

動いているのは常に `%APPDATA%\DesignTaskBoard` の自動起動用コピー。このコピーが新しくなるのは、
**本人が共有フォルダの `kanban_relay.py` をダブルクリックしたときだけ**。

- ダブルクリック: 自動起動用コピーを新しくし、動いていれば再起動、止まっていれば画面なしで起動してボードを開く
  （ファイルが同じでも設定と Redmine のメンバーを読み直す）。更新の取り込み元も、このフォルダに向け直す（`update_dir` の指定がない場合）。
  再起動の依頼に応じない古い版が残っていたら、そのプロセスを止めて自動起動用コピーを起動し直す。
- ログオン時: 共有フォルダのプログラムは**自動では入れ替えない**（v13 から）。共有フォルダに書ける人なら誰でも
  全員の PC で黙ってプログラムを動かせてしまうため。新しい版（`VERSION` と画面の作成日時 `BUILD` で判定）があれば、
  ボードを開いたときに「共有フォルダの kanban_relay.py をダブルクリックすると更新されます」と知らせる。
  `board_settings.json` だけは取り込む（接続先が変わっていれば下の「API キーの送り先の固定」で止まる）。

配布する人は `board_settings.json` の `update_dir` に共有フォルダを書いておくと、取り込み元がぶれない。
`--uninstall` で自動起動を解除、`--setup` で API キーを設定し直す。
API キーは Windows の DPAPI で暗号化して `%APPDATA%\DesignTaskBoard` に保存する。ブラウザには置かない。
どの版が動いているかは「接続設定」の下（中継プログラムの版とフォルダ）で確認できる。

### 中継プログラムの安全対策

- 127.0.0.1 でだけ待ち受け、Host ヘッダーが 127.0.0.1 / localhost 以外なら断る（DNS リバインディング対策）。
- API を使えるのは、中継が出したボードのページ（同一オリジン）と `ALLOWED_ORIGINS` に書いたページだけ。
  他の Web サイトからの呼び出しは、Origin / Sec-Fetch-Site で判定して断る。
- **API キーの送り先の固定**（v13 から）: API キーを設定したときの接続先（スキーム・ホスト・ポート）を `relay.json` に一緒に保存し、
  `board_settings.json` の `redmine_url` がそれと違えばキーを送らない。ログオン時の起動はそこで止まり、
  ダブルクリックしたときは「この接続先に API キーを送ってよいですか？」と聞く（`yes` と入力したときだけ送り先を変える）。
  以前の版で設定したキーは、この版に更新したときの接続先を 1 回だけ記録する。`http://`（暗号化なし）の接続先には警告を出す。
- 共有フォルダのプログラムを自動では入れ替えない（上の「更新」）。共有フォルダは書き込みできる人を配布担当に限るのが望ましい。
- Windows 以外では API キーを暗号化できないので、本人だけが読める権限（600）で保存し、保存時と起動時に警告を出す（開発・確認用）。
- 中継するのはボードが使う API（チケットの参照・更新、バージョン、ユーザー情報、作業時間の参照・記録、チケットの前後関係の参照・追加・削除）だけ。

## 列とステータスの対応

| 列 | Redmine ステータス | ドロップ時に設定 |
|---|---|---|
| 未着手 | 未着手 | 未着手 |
| 進行中 | 0% / 20% / 40% / 60% / 80% | 0%（カード内ボタンで 20〜80% に変更） |
| 担当完了 | 完了（実務者） | 完了（実務者） |
| 上司完了（上司の画面だけに表示） | 完了（確認済）（直近14日のみ表示） | 完了（確認済）（上司のみ） |
| （非表示） | 中止 | ドラッグ中に出る「中止」ゾーンへドロップ |

ステータス ID は `CONFIG.statuses` で実環境に合わせる。

## 名前のルール（画面はこれを読んで動く）

- **対象バージョン名の先頭の数字 = 優先度**（`01_不具合対応` → 1）。カードはこの番号の小さい順、
  同じ番号の中では締切の近い順に並ぶ。`CONFIG.urgentPriority` 以下（初期値 01）は赤いタグになる。
- **バージョン名は「番号_カテゴリ-個別名」**（例: `05_開発業務-EV電池ケース`）。カードのタグには個別名を出す。
  新しいバージョンもこの形で作る（`versionCategories` の末尾の区切りをそのまま使う）。読むときは区切りが「_」の古い名前も読める。
- **件名の先頭の【M/D】 = 本来の締切**。期限の強調はこの日付で判定する。
  Redmine の期日は「作業完了予定」として小さく表示し、締切より後なら「締切超え」と出す。
  【M/D】がない場合は Redmine の期日で代わりに判定する。
- タグの色は名前から自動で決まる（毎回同じ色）。固定したい場合は `CONFIG.versionColors`。

## ★ 優先してほしい

- カードの右上の ☆ を押すと ★「優先」になる（もう一度押すと外れる）。編集画面の「★ 優先してほしい」でも同じ。
- 保存先は Redmine の **優先度**（新しい項目は作らない）。付けると既定（通常）の 1 つ上（ふつうは「高め」）、外すと既定に戻す。
  Redmine で既定より上の優先度になっているチケットも ★ と表示する。優先度の一覧（`/enumerations/issue_priorities.json`）が読めなければ ☆ は出さない。
- 並び: 余裕が少ない順では 緊急 → ★優先 → 余裕の少ない順。いつもの順では、並び替えで決めた順番は崩さず、まだ順番を決めていないカードの中で ★ を先に。
- ★ のカードは枠が黄色。サマリーに「★優先」の件数。課題バラシの箱にも「★優先」を出す。

## 詰まりのサイン（待ち・止まっている・手持ちの上限）

- **待ち**: 前の仕事（課題バラシの矢印 = Redmine の先行）が終わっていない未着手・進行中のカードに「⏳ 待ち: 伊藤「○○」」（自分の仕事なら「自分」）。
  前の仕事がすべて終わった未着手のカードには「✓ 前の仕事が終わりました。着手できます」。つながりは一覧の `include=relations` でまとめて読む。
- **止まっている**: 進行中のカードで、ステータス（進捗）が `staleDays`（既定 5）営業日以上変わっていなければ「N日動きなし」。
  変更履歴のステータス変更日で数える（日程の書き直しやコメントでは動いた扱いにしない）。全体ボードのタイルにも件数を出す。
- **手持ちの上限**: 進行中が `wipLimit`（既定 5）件を超えたら、列の見出しに「上限5件を超えています」。
- サマリーに「待ち」「止まっている」の件数。待ち・止まっているは画面を出したあと裏で読む（失敗しても画面は止めない）。
- `staleDays`・`wipLimit` は `board_settings.json` の `options` で変えられる。

## 自分の作業順（列の中で上下に並び替える）

「未着手」「進行中」の列の中でカードを上下にドラッグすると、その人の仕事を **進行中（上から）→ 未着手（上から）** の順に詰めて、
開始日と作業完了予定（期日）を決めて Redmine に書く。並び順はこの日付として保存される。

- 期間は予定工数 ÷ `hoursPerDay` を営業日に切り上げ（未入力は 1 日、進行中は残りの分）。土日と `options.holidays` は休み。
- 課題バラシでつないだ前の仕事（先行）が終わっていなければ、その期日の翌営業日まで後ろにずれる。順番が先行関係と合わないときは警告を出す。
- 進行中の仕事の開始日はそのまま（前の仕事を待つ場合だけ後ろへ）。終わりの予定だけ決め直す。
- 並び順: 未着手は開始日が今日以降のもの（並び替えで日程を決めたもの）を開始日順、ほかはその後ろに いつもの順（バージョン番号 → 締切）。
  進行中は作業完了予定の順、期日がないものは後ろ。Redmine は新しいチケットに作成日を開始日として入れるので、過去の開始日は並び替えの印とみなさない。
- 1 回の並び替えで、その人の進行中・未着手の日程をまとめて書き直す（手で入れていた作業完了予定も上書きする）。「元に戻す」で戻せる。
- 別の列へのドラッグは今までどおりステータスの変更。
- **並び: 余裕が少ない順**（上の数字の並びの右で切り替え）: 未着手・進行中を表示だけ並べ替える。
  緊急（バージョン番号が `urgentPriority` 以下）は常に上、それ以外は **余裕 = 締切（【M/D】、なければ期日）までの営業日数（今日を含む）− 残りの作業日数**
  （予定工数 ×（1 − 進捗率）÷ `hoursPerDay` を切り上げ、未入力は 1 日分）の少ない順、同じなら いつもの基本順。締切がないものは下。
  カードに「余裕 N日」（マイナスは赤、1日以下は黄、緊急は「緊急」）を出す。
  この並びのあいだは上下の並び替えはできない。「この順番で日程を決める」を押すと、この順を作業順にして日程を決め、いつもの順に戻る。

## 新規タスク（担当なしで「未整理」へ）

「＋ 新規タスク」で担当のチェックを外す（またはバージョンを空にする）と、ボタンが「未整理に登録」になり、
とりあえず 1 件作って「未整理」タブに入れる。あとで誰かが担当とバージョンを決めて振り分ける。

## カードの編集

カードをクリック（または選んで Enter）すると編集画面が開く。締切【M/D】・件名・作業完了予定・
対象バージョン・担当・説明を直せて、コメントを追加すると Redmine の履歴に残る。
変更した項目だけを送り、保存後に読み直して反映を確かめる。権限で無視された項目があれば名前を出す。
担当を変えるとカードはその人のボードへ移る。
ステータスはこれまでどおりドラッグ（進行中は進捗ボタン）で変える。

## 新規タスクとバージョンの作成

ヘッダーの「＋ 新規タスク」で、編集画面と同じ入力欄からチケットを作る（表示中のメンバーが担当の初期値）。
担当はチェックボックスで複数選べ、選んだ人数分の同じチケットを作る（E-ラーニングなど全員がやる仕事向け）。
未整理の振り分けでも同じで、元のチケットは1人目の担当になり、2人目からは同じ内容で新しく作る。
2人以上を選ぶと「まとめ用の親チケットを作る」が出る（初期はオン）。オンなら「件名（全員）」の親チケットを作り
（未整理では元のチケットを親にする）、各自のチケットをその下に入れる。全体タブの「みんなでやる仕事」で、
完了した人数と、まだの人の名前を一か所で見られる（同じ親の下に同じ件名の子が2人以上あるものだけ。全員終わると消える）。
対象バージョンの横に「＋ 新しいバージョン」が出る（全員）。優先番号（01〜09）と名前から
業務カテゴリと個別名から `05_開発業務_EV電池ケース` の形で作る。権限がなければその旨を表示する。

## 全体（ダッシュボード、全員が見られる）

Teams の画面共有でみんなで見る前提で、文字を大きくし、1画面に収める。

- 上段: チームの数字（締切超過・今週の締切・2週間で完了・日程の見直しが必要な仕事）
- 左（主役）: メンバーの状況。2つの表示を切り替えられる（どちらを見ていたかはブラウザが覚える）
  - 積み木: 締切超過と間近のタスクだけ、名前が読める固定幅のブロックで出す（1人4件まで）。
    残りは「ほか N件」の1ブロックにまとめ、その長さを残りの作業量（未着手 1.0、進行中は残りの割合）に比例させる。
    1人30〜40件でも1画面に収まる。乗せると中身の一覧。残作業量の多い順に並べる
  - タイムライン: 平日だけ、今日を境に左がこれまでの完了（変更履歴から完了の列に入った日）、
    右がこれからの締切。週末の分は金曜に含める
  - 行をクリックするとその人のボードへ
- 右: 仕事ごとの状況。バージョンの個別名ごとに、進捗とバッファ消費の2本のバー
  - バッファ = 本来の締切【M/D】 − 作業完了予定。締切が前後2週間のタスクだけで測る
    （後から増えるタスクで進捗が下がり続けないように）
  - 見直し = 消費が 30% + 進捗×70% を超えた、注意 = 10% + 進捗×60% を超えた

## 親チケットのステータスの自動更新

Redmine 本体は親チケットのステータスを変えないので、ボードで子に合わせる（すべての親子関係、親の親までさかのぼる）。

| 子チケット（中止は除く） | 親のステータス |
|---|---|
| 全員 未着手 | 未着手 |
| 全員 完了（確認済） | 完了（確認済） |
| 全員 完了（実務者）以上 | 完了（実務者） |
| それ以外 | 子の進捗の平均（未着手 0・完了 100）を 20% 刻みで切り捨て |

- ボードで子のステータスを変えたとき（ドラッグ・進捗ボタン・中止）に動く。
- Redmine の画面で直接変えた分は、上司が「全体」タブを開いたときにまとめて合わせる（10 分に 1 回まで、裏で実行。メンバーが開いたときは行わない）。
- 親が「中止」や、ボードが知らないステータスのときは触らない。ワークフローで拒否されたときは表示する。

## 工数（Redmine の作業時間）

- **進捗を動かしたとき**（自分のカードで進行中・担当完了にしたとき）、画面右下に `0.5h / 1h / 2h / 4h / 1日(8h) / 記録しない` が出る。
  押すとそのチケットに今日の作業時間として記録する。押さなければ何も記録しない（20 秒で消える）。
  聞かれたくない人は「接続設定」の「工数」でオフにできる。
- **「工数」ボタン → 日々の記録**: その日に動かしたチケットと記録済みの時間が並ぶ。`+1` などで足して「記録する」。
  合計が所定時間（`hoursPerDay`、既定 8h）に届いているかが見える。日付を変えれば過去の日にも記録できる。
- **ほかの人のチケットにも記録できる**（手伝い・レビュー・打合せなど）。記録はいつも自分の作業時間になる。
  - カードの編集画面の「作業時間を記録」（`+0.5h` 〜 `+1日`）。ほかの人のタブのカードや、課題バラシの箱（ダブルクリック）からも。
  - 「日々の記録」の「ほかのチケットを追加」に「ほかの人の仕事」のグループ（担当名つき）。一覧にないものは `#番号` で追加。行には「担当: ○○」を出す。
- **「工数」ボタン → 月の集計**: 月ごとに、バージョン別（またはプロジェクト別）× 人の合計時間。自分だけ / チーム全員を切り替え、CSV で保存できる。
  サブプロジェクトで分けているチームは「プロジェクト別」を使う。
- 作業分類は Redmine の既定のもの（既定がなければ一覧の先頭）を自動で付ける。記録の修正・削除は Redmine の「作業時間」画面で行う。
- 他の人の記録を集計するには、Redmine の「作業時間の閲覧」権限が要る。

## 課題バラシ（タスクの分解と前後のつながり）

「課題バラシ」タブ、または未整理タブの「課題バラシで分解する」から開く。範囲はバージョン 1 つ、親チケット 1 つ、または担当者 1 人（上の選択欄で切り替え）。

- **並び方**: つながった仕事は同じ行に横一列で並べ、分かれた先だけ下の行に出す（矢印が交差しにくい）。長い流れほど上の行、つながりのない仕事は下。
  右から左へ戻る矢印は箱の下を回す。
- **並び順の切り替え**: 「つながり優先」（長い流れを上に、そのあとバージョン番号 → 締切）と「締切が近い順」（締切【M/D】、なければ作業完了予定。
  枠は自分と中の未完了の仕事のうち、いちばん近い締切）。どちらでも、つながった仕事は同じ行に横一列で並ぶ。
- **担当者ごと**: その人の担当タスク（未完了と直近の完了）を、所属する親の枠に入れて並べる。親の枠は文脈として出すだけで（「この人の分だけ表示」）、
  Redmine に新しい親チケットは作らない。他の人のタスクとのつながりは、箱の中に「⏳ 待ち: 伊藤「○○」」「→ 次: 渡辺「○○」」と出す
  （範囲の外とのつながりは、どの範囲でも同じように出す）。

- **親子 = 枠の入れ子**。中の仕事（子）は親の枠の中に入る。孫は枠の中の枠。
- **前後 = 左から右への矢印**。Redmine の「先行（precedes）」として保存されるので、ガントチャートにも同じ矢印が出る。
  並行できる仕事は縦に並ぶ。別の枠の仕事どうしもつなげる。
- 操作: 枠のいちばん下の「＋ ここに追加」で同じ階層に（つながりのない）仕事を追加／箱の ＋（左・右・下）で前・後・中の仕事を追加（名前を入れて Enter で Redmine に作る。名前を入れずにやめれば作らない）／
  箱をドラッグ（相手の左端＝前、右端＝後、真ん中＝中に入れる）／⤳ をドラッグで矢印だけ／矢印をクリックで外す／
  ダブルクリックか ✎ で編集画面（担当・締切・説明など）／F2 で名前だけ変える／× で中止（チケットは残る）。
- 新しい仕事は、元の箱の担当・バージョンを引き継ぐ。
- **予定工数**: 箱の「予定工数 ＋」から入れる（Redmine の予定工数）。枠には中の合計と、工数ボタンで記録した実績が出る。実績が予定を超えると赤。
- **完了を隠す**（既定でオン）: 完了した仕事（中がすべて完了した枠も）を画面から外し、左の欄に新しく終わった順で小さく並べる。
  残りの仕事は左に詰まる。このとき「一番長い流れ」は残りの仕事だけで数える。
- **ステータスの変更**: 箱のステータス表示（「未着手 ▾」「40% ▾」）を押すと選択肢が出る。親チケットも子に合わせ、自分の仕事なら作業時間を聞く（ボードと同じ）。
  「上司完了」は上司だけに出す。
- **担当の変更**: 箱の担当者名（「高橋 ▾」）を押すとメンバーの一覧が出る。「担当を外す」もできる。枠（親チケット）の担当も変えられる。
- **バージョンのタグ**: 担当者・親チケットの範囲では、箱の左上にバージョンのタグを出す（バージョンの範囲では全部同じなので出さない）。
- **日程の自動計算**: 予定工数と矢印の順番から、各タスクの開始日と作業完了予定（Redmine の期日）を計算して箱に 📅 で出す。
  - 先頭（前の仕事がない）の仕事は、自分の開始日があればその日、なければ上の「着手」の日（既定は今日）から。
  - 前の仕事がある仕事は、前の仕事がすべて終わった翌営業日から（範囲の外の仕事とのつながりも、その期日を見る）。
  - 期間 = 予定工数 ÷ `hoursPerDay` を営業日に切り上げ（未入力は 1 日として計算し「工数未入力→1日」と出す）。進行中は残りの分だけ。
  - 土日と `options.holidays` は休み。完了した仕事は動かさない。親チケットの日付は Redmine が子から決めるので書かない。
  - 「工数を入れたら日程も反映」（既定でオン）: 予定工数を入れた仕事と、その後ろにつながる仕事だけ Redmine に書く（ほかの手入力の日程は触らない）。
  - 「日程を反映（n件）」: 表示している範囲で、計算と Redmine の値が違うもの（「未反映」）をまとめて書く。開始日の早い順に書く。元に戻せる。
  - 計算した作業完了予定が件名の締切【M/D】を超えると「締切超え」。
- **一番長い流れ**: 予定工数の合計がいちばん大きい矢印の連なりを赤く出し、時間と日数（`hoursPerDay` で換算）を表示する。
  並行できる仕事を除いた「順番にしかできない仕事」の合計なので、締切に間に合うかの目安と、CCPM のバッファを決める基準に使える。
- 未整理のチケットを分解するときは、件名・締切・バージョンを保存してから開く（担当はなくてよい）。中に仕事ができると未整理から外れる。
- 注意: 「先行」でつなぐと、前の仕事の期日が延びたとき Redmine が後の仕事の開始日・期日を自動でずらす（ガントチャートと同じ動き）。
  親と中の仕事どうしはつなげない（Redmine の制限）。親を変えるときは、新しい親・祖先とのつながりを先に外す。

## 未整理タブ（新規タスクの振り分け）

Power Automate がメールから作った、担当またはバージョンが未設定のチケットを一覧にする。
選んで「締切」「件名」「対象バージョン」「担当」「作業完了予定」「説明」を入れて登録すると、
件名の先頭に【M/D】を付けて Redmine を更新し、担当者のボードの「未着手」に入る。
メールのノイズ（「教えてください」など）は「タスクではない」で中止にする。チケットは削除しないので、
Power Automate の重複判定はそのまま使える。
対象を特定のプロジェクトに絞る場合は `CONFIG.projectId` を設定する（全員共通の設定なのでファイル側に書く）。

## 親チケットの表示

子チケットを持つチケットは「中項目（まとめ用）」とみなし、担当や期日の有無にかかわらず未整理に出さない。

親、親の親…とたどり、カード上部に `祖父 › 親` の形で直近 2 階層を表示する（全階層はマウスを乗せると出る）。

## 社内 AI に引き継ぐときの範囲

画面の設定は中継が `/*__SERVER_CONFIG__*/` の位置で `CONFIG` に差し込む。Redmine との通信は `createRedmineApi()` だけ。
画面側は `currentUser / issuesFor / issuesByIds / inboxIssues / versions / updateIssue` の 6 関数にしか依存しない。
